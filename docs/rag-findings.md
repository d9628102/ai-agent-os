# PSF EIM RAG 問答:實測結果與已知限制

記錄 `scripts/rag_answer.py` 在 GX10 上針對 `psf_eim_kb` 的實測結果。
測試集為 `scripts/data/psf-eim-qa-questions.txt`(5 題內容問題 + 1 題
負向對照)。

> **樣本數警告**:以下每種設定都只跑過**一次**。趨勢明確的項目(例如
> 耗時差異達 4.8 倍)可以採信,但涉及回答品質的細微差異(例如越界抑制
> 效果)在單次測試下**不足以下定論**,待補測見文末。

## 思考模式開關的 A/B 對比

同一組 6 題,思考模式開啟／關閉的差異:

| 問題 | 思考開啟 | 思考關閉 | 加速 |
|---|---|---|---|
| 五大產品矩陣 | 19.21s | 4.56s | 4.2× |
| Decision Matrix 核心模組 | 14.54s | 2.60s | 5.6× |
| 跟 ERP/CRM 的差異 | 31.12s | 9.44s | 3.3× |
| 負責客戶服務的 Agent | 17.19s | 1.56s | 11.0× |
| 架構分成幾層 | 15.10s | 3.20s | 4.7× |
| 定價(負向對照) | 14.65s | 1.89s | 7.8× |
| **平均端到端** | **18.63s** | **3.87s** | **4.8×** |

輸出 tokens 從 2379 降到 446 —— **約 81% 的生成量是使用者看不到的推理
內容**。tokens/s 兩者都在 16–22 之間,幾乎沒變,所以加速完全來自產出量
減少,不是吞吐提升。

耗時結構:**生成佔 99.8%**。embedding 約 0.03–0.05 秒、Qdrant 檢索約
0.00–0.01 秒,兩者相對於生成可以視為免費。要再壓低延遲只有從生成端下手。

## 正確性

兩種設定下,**5 題內容問題的事實全部正確**,沒有捏造任何 PSF 產品、模組
或 Agent 名稱。

**負向對照(定價)在兩種設定下都守住了** —— 都明確回答「文件中未提及」,
沒有編造價格。防幻覺的保護**不依賴思考模式**。

## Known Issue #7:`--think` vs `--no-think` 對回答品質與速度的取捨(待補測)

> 編號說明:此編號屬於本文件(RAG 行為)的獨立序列,與
> `docs/gx10-known-issues.md` 的 #1–#7(環境建置問題)是不同的兩套編號。
> 那份文件的 #7 是 HF_TOKEN 非 ASCII 字元的問題。

**現象**

關閉思考模式(`--no-think`)平均可帶來 4.8× 生成加速(18.63s → 3.87s),
且事實正確性、防幻覺(負向對照題)皆未退步。但單次測試觀察到,關閉思考
模式後:

- 可能遺漏「命名易混淆」情境下的辨析(例如 Q4:Service Matrix 的 Core
  Module「Customer Success」與 Agent Matrix 底下的「PSF Customer Success
  Agent™」,兩者是否為同一實體,思考開啟版本會主動釐清,關閉版本未辨析)
- 可能遺漏列舉型問題的完整組成細節(例如 Q5:四層架構名稱,思考關閉版本
  只列層名,思考開啟版本會列出各層組成元件)
- 偶爾出現文件中未提供譯名的自行補充翻譯(程度輕微,屬翻譯而非事實捏造)

**原因**

思考模式(reasoning)讓模型有機會在生成最終答案前,先對照文件內容做一輪
消歧義與完整性檢查;關閉後省去這個步驟,直接輸出結論,速度大幅提升但
可能跳過需要「多想一步」才能發現的細節。

**目前狀態:已完成重複測試,差異確認為穩定,非抽樣雜訊**

2026-09-07 以 `scripts/run_think_ab_test.py` 完成重複測試:固定新 system
prompt,Q3/Q4 兩題 × 思考開啟／關閉 × 各 3 次獨立子行程 = 12 次生成。
逐次判讀結果(原始逐次回答見
[`docs/think-mode-ab-test-results.md`](think-mode-ab-test-results.md)):

| 題目 | 模式 | 第1次 | 第2次 | 第3次 | 出現機率 |
|---|---|---|---|---|---|
| Q3 越界 | think 開啟 | 無 | 無 | 無 | **0/3** |
| Q3 越界 | think 關閉 | 有 | 有 | 有 | **3/3** |
| Q4 辨析保留 | think 開啟 | 有 | 有 | 有 | **3/3** |
| Q4 辨析保留 | think 關閉 | 無 | 無 | 無 | **0/3** |

兩個指標都是 **0/3 對 3/3 的極端分離**,沒有 2/3 vs 1/3 這種模糊比例,
因此可判定為**穩定的系統性差異**,不是單次抽樣運氣。耗時同樣穩定:
思考開啟 41.3/42.0/40.7 秒,關閉 10.4/10.4/10.1 秒(每次含 2 題),
組內變異都在 1.5 秒內,**4.0× 的速度差同樣穩定**。

**混淆變因已排除**:本次兩組都使用**同一份**加嚴後的 system prompt,
唯一變數是思考模式。結果顯示加嚴的 prompt **單獨不足以**防止越界
(思考關閉時仍 3/3 發生),真正發揮作用的是思考模式本身。

**重要的認知修正:Q3 其實是第二題負向對照,而先前沒有意識到**

文件只寫了「PSF EIM 並不是 ERP、CRM」,**從未說明 ERP/CRM 是什麼、
做什麼**。因此嚴格有依據的回答應該是「文件不足以支撐這個比較」。

- **思考開啟 3/3 正是這樣回答**:「文件中未提及足夠資訊以說明兩者差異」,
  明確拒絕比較,並說明文件只講了我方定位。
- **思考關閉 0/3**:每一次都「生出」一個比較,用世界知識補上文件的空白
  (「ERP 和 CRM 通常聚焦於企業資源規劃與客戶關係管理」等)。

這修正了先前記錄的「關閉思考時事實正確性與防幻覺皆未退步」——**在這類
文件無法支撐的問題上,關閉思考確實會讓 grounding 退步**。它沒有捏造 PSF
自身的事實,但會(a)對第三方做出無來源的斷言,(b)不告訴使用者「文件其實
回答不了這個問題」。第 (b) 點比第 (a) 點更值得注意:使用者會拿到一個看起來
完整、有結構、實則部分無來源的答案,而且沒有任何警訊。

**暫定作法(建議重新評估)**

目前程式碼狀態:`scripts/rag_answer.py` 思考模式**預設關閉**,需要時加
`--think`。(舊的 `--no-think` 旗標已移除,誤用會直接報錯而非被靜默忽略。)

這是在「品質差異可能只是抽樣雜訊」的前提下做的決定。該前提現已被推翻,
建議重新評估,選項:

1. **改回預設開啟**:確保 grounding,代價是日常查詢從 ~5s 變成 ~20s
2. **維持預設關閉,但依問題類型動態切換**:偵測到比較句型
   (「跟…有什麼不同」「相較於」「vs」)或涉及多個相似命名實體時自動改用
   思考模式 —— 兼顧兩者,但需要額外實作與驗證
3. **維持現狀**,接受比較類問題的 grounding 風險,並在使用說明中告知同事
   這類問題要自己加 `--think`

**待辦**

- [x] 針對 Q3、Q4,各將「新 prompt + 思考開啟」與「新 prompt + 思考關閉」
      重複執行 2-3 次,觀察越界／辨析遺漏的出現機率 —— **已完成,3 次重複,
      結果為 0/3 vs 3/3 的穩定分離**
- [ ] 依上述結論決定 Phase 1 預設(三個選項見「暫定作法」)
- [ ] **擴充負向對照**:目前明確設計的只有「定價」一題,而 Q3 意外成為
      第二題。建議再補幾題文件確實沒有的主題(例如導入時程、技術規格、
      競品比較),特別是**比較型**的負向對照,確認上述現象的範圍
- [ ] 若採用動態切換,需驗證句型偵測的誤判率(把不需要思考的問題誤判為
      需要,會白白付出 4× 的延遲)

**試用期間的因應**:若同事回報「答案感覺沒講清楚」,可請他們在問題後
加註要求更詳細說明,或改用 `--think` 重問。**另外提醒同事:詢問
「PSF EIM 跟 X 有什麼不同」這類比較型問題時,建議直接加 `--think`**,
否則答案中關於 X 的描述可能不是來自內部文件。
